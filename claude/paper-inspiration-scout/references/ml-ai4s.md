# ML / AI4S 粗读检查

仅当机器学习是论文的主要论证手段时读取。只展开会改变文章模型、灵感卡或验证方案的项目，不把粗读变成逐项审计。

## 问题与数据

- 输入 `X`、输出 `Y`、约束 `C` 和预测或决策的基本单位是什么？
- 任务是预测、生成、反演、优化、控制还是表征学习？模型输出如何连接到科学问题？
- 论文优化的是最终科学目标还是代理指标；两者靠什么假设连接？
- 数据来自实验、模拟、公开数据库还是模型生成；规模、版本、标签生成和预处理是什么？
- 训练、验证、测试怎样划分；划分单位是否与科学外推目标一致？
- 测试分布与部署、模拟或湿实验场景之间差在哪里？是否存在泄漏或捷径？

## 模型与训练

- 表示、模型结构、损失函数和训练策略分别承担什么作用？
- 物理约束、守恒律、对称性、等变性、先验或归纳偏置具体进入表示、结构、损失还是采样过程？
- 关键收益来自模型本身，还是更多数据、预训练、算力、搜索预算或后处理？
- 记录足以影响复现的优化器、学习率策略、停止规则、随机性和主要算力条件。

## 评估与证据

- baseline 是否使用可比的数据、特征、调参预算和评估协议？
- 指标是否回答科学问题；平均性能是否掩盖关键子群、极端区域或失败模式？
- 消融是否真正隔离核心设计；外推、校准、不确定性、鲁棒性和效率只在与论文主张有关时展开。
- 区分回顾性 benchmark、前瞻性模拟验证和真实实验闭环。模型提出候选但未被后续模拟或实验检验，不称为闭环验证。
- 代码、数据、划分、检查点和环境是否可获得；缺少哪一项会阻塞核心结果复现？

## 灵感来源

优先检查：改变问题形式化；用新表示暴露对称性、局部性或守恒关系；把科学约束放进结构、损失、采样或解码；重组模拟、实验、弱标签或多保真监督；用不确定性或主动学习决定下一次采样；用 OOD、机制指标或闭环实验改变“有效”的判据。

生成灵感卡时说清收益来自哪一个动作；论文不能隔离它时，把这一点写进关键假设。

## 最小验证

1. 选择能暴露目标瓶颈的最小代表性数据子集和固定划分。
2. 选择一个可信基线，只加入灵感卡中的核心变化，保持其余训练条件可比。
3. 同时设置任务指标和与科学目标直接相关的读出；随机性会改变结论时使用足以判断方向的重复运行。
4. 预先写出成功、无效和反效果的判据，并检查最可能的数据泄漏或捷径。
5. 核心变化显示可重复信号后，再扩大数据、模型或闭环成本。

## 复现清单

最小复现至少核对：数据版本与划分、预处理、表示、模型配置、损失、训练策略、停止规则、随机种子或重复方式、指标实现、硬件量级和目标结果。完整复现再加入全部超参数搜索、消融、OOD、效率、不确定性以及下游模拟或实验闭环。把原文未报告和当前材料不可见的参数分开列出。
