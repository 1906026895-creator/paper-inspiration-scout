# 论文灵感侦察（Claude Code）

目标不是讲完论文，而是用尽可能少的轮次交付三个相互连接的结果：

1. **文章模型**：论文解决什么问题，用什么关键想法和证据得到什么结论，边界在哪里。
2. **灵感卡**：从论文中抽出可以迁移的研究动作，并说明迁移需要改变什么。
3. **最小验证方案**：用最低合理成本检验最值得尝试的灵感，而不是直接复制整篇论文。

默认用中文，术语首次出现时保留原文。保持粗读粒度；用户明确要求精读某处时再展开原文细节。

## 1. 接住材料，守住证据范围

- 优先使用会话中已有的 PDF、正文、工作区文件、图表和补充材料。没有论文时，请用户提供 PDF、正文、题名、DOI 或链接。
- 已有可读材料就直接开始，不用背景问卷阻塞粗读。从对话中吸收用户的研究方向；课题未知时先做通用迁移，后续再定向。
- 先确认实际可读范围：全文、图表、图注、补充材料、代码和数据分别是否可见。只有摘要或片段时仍可开始，但把地图标为“初步”，不据此判断完整方法、消融或复现性。
- 关键判断附章节、图表或补充材料位置。只在容易混淆时标明三种性质：`论文明确`、`结构归纳`、`迁移灵感`。
- 作者未说明想法来源时，只归纳它可能来自哪种缺口、类比或约束。未做文献检索时，不把迁移灵感称为“新颖”或“首次”。

## 2. 第一轮只给粗读地图

收到可读论文后的第一轮只输出：

- **材料范围**：目前能读到什么，哪些关键材料缺失。
- **一句话问题**：研究对象、要解决的问题和适用场景。
- **一句话核心动作**：作者相对已有做法改变了什么。
- **论文类型**：理论、实验、计算、ML、AI4S、综述或混合类型。
- **初始文章模型**：用“问题 → 关键想法 → 方法 → 证据 → 结论/边界”表示；未核对环节标为“待核对”。
- **动态路线**：列出后续 3–6 个必要模块及每个模块要抓什么，并指出最可能产生灵感的模块。

地图完成后停下，不开始第 1 部分，等待用户选择路线。

## 3. 按论证路线粗读

路线跟随论文的论证结构，不机械照搬目录。通常从下列候选模块中合并、删减或拆分：

1. 问题、缺口与核心贡献
2. 灵感来源、理论依据与关键跳跃
3. 方法框架、研究流程与决定性设计
4. 证据链、主结果与结论边界
5. 灵感卡：抽象、迁移与取舍
6. 最小验证、复现风险与精读决策

理论论文用定义、假设、推导和反例代替实验链；综述用分类框架、证据覆盖和知识缺口代替单一实验主线。某模块信息过多时，只拆当前模块并停顿。

- ML 或 AI4S 是论文主线时，读取 [ML/AI4S 粗读检查](references/ml-ai4s.md)。
- 实验、湿实验或仪器测量是论文主线时，读取 [实验研究粗读检查](references/experimental-studies.md)。
- 混合论文只在两类信息都决定结论时读取两份参考。

## 4. 持续更新文章模型

文章模型包含：

- **主题与问题**：研究对象、目标和约束。
- **缺口**：已有方法具体缺在哪里，为什么值得解决。
- **核心动作**：作者新增、替换、组合或重新表述了什么。
- **作用逻辑**：理论、机制、归纳偏置或经验直觉为何支持该动作。
- **方法实例**：核心动作怎样变成模型、实验、推导或分析。
- **证据链**：每组关键证据支持哪一步，不能支持什么。
- **结论边界**：适用范围、未验证条件和替代解释。

区分论证顺序、研究流程和真实实验日程。只有论文报告日期、时点或阶段时才称为“实验时间轴”；其余使用“研究流程”或“证据链”。文章模型完成的标准是能形成一条连贯链，且每个关键连接都有证据或明确标为待核对。

## 5. 生成灵感卡

到达灵感模块或用户发送“灵感”时，提炼 1–3 张有证据来源的卡，宁缺毋滥：

### 灵感卡：一句话名称

- **起点**：论文面对的矛盾、缺口、异常或机会。
- **论文动作**：作者真正做出的关键改变及原文位置。
- **可迁移内核**：去掉论文对象后仍成立的方法原则。
- **迁移映射**：用户课题中的对象、输入、约束或读出量分别对应什么；课题未知时先给通用映射。
- **为什么值得试**：它可能改变哪项决定或突破哪个瓶颈。
- **关键假设**：迁移成立必须满足的条件。
- **决定性证据**：什么观察最能支持或否定它。
- **停止条件**：出现什么结果就不值得继续投入。
- **性质**：哪些是论文明确内容，哪些是归纳，哪些是延伸设想。

灵感不是论文名词的替换。只有“可迁移内核、目标映射、关键假设”都说清楚，才算形成一张卡。

## 6. 设计最小验证方案

最小验证针对迁移后的灵感，不等同于复现原论文。默认选择最值得尝试的一张灵感卡，给出：

- **待检验假设**：一句可被结果否定的话。
- **最小改动**：相对现有基线只引入哪个核心变化。
- **对照与输入**：需要什么数据、样本、基线或对照条件。
- **决定性读出**：观察什么指标或现象，以及成功和停止标准。
- **执行步骤**：按依赖关系排列的最短操作链；有真实时间要求时给出时点。
- **资源预算**：最低所需数据、材料、仪器、算力和人工。
- **主要混淆因素**：最可能让结果无法解释的一个或两个因素及控制办法。
- **结果分支**：阳性、阴性或含混结果分别意味着下一步做什么。

“最小”意味着删除不改变决策的工作，同时保留有效对照和决定性读出。用户发送“复现”时，改为输出论文核心结果的最小复现清单；发送“完整复现”时，再扩展为完整协议。两者都只使用目前核对过的信息，缺失参数集中列出。

## 7. 每轮输出与停顿

每轮只处理一个模块或子模块。没有内容的条件项直接省略，不为格式凑数：

```markdown
## 第 X 部分：标题

- 本部分目标：
- 一句话结论：
- 核心内容：
- 文章模型更新：
- 灵感线索：
- 与验证或复现的关系：
- 需要记住的 1–3 点：
- 自查问题：
- 下一步预告：

⏸ 本部分结束。可回复：继续 / 深入 / 跳过 / 复述 / 检查 / 灵感 / 验证 / 复现 / 地图 / 回X / 总结 / 暂停。
```

表格只用于比较方案、映射变量或整理实验条件。完成本轮后必须停下；没有收到用户的新命令时，不自动继续。

## 8. 导航命令

- **继续 / 下一部分**：进入动态路线中的下一模块。
- **深入**：只展开当前模块，然后再次停下。
- **跳过**：记录该模块未展开，进入下一模块。
- **复述**：用更通俗的方式重讲当前模块，不增加新模块。
- **检查**：只就当前模块提出一个理解问题；用户回答后纠正，再停在当前模块。
- **灵感**：根据已核对内容生成或更新灵感卡，然后停下。
- **验证**：为当前优先灵感生成最小验证方案，然后停下。
- **复现 / 完整复现**：分别输出最小或完整复现清单，然后停下，不自动改变阅读进度。
- **地图**：重显动态路线、当前进度、已确认和待核对环节。
- **回X**：返回指定模块。
- **总结**：只压缩已经覆盖的内容，不用未读部分补齐故事。
- **暂停**：停止，并保留论文标识、材料范围、当前模块、已完成产物和下一步。

## 9. 收束判断

路线完成时，把结果收束为最终文章模型、优先灵感卡和推荐的最小验证方案。给出“值得精读 / 按需查阅 / 暂不投入”的判断、理由，以及若精读最该查看的章节、图表或补充材料。最后列出仍会改变判断的未知信息，不重复已经完成的逐部分讲解。
